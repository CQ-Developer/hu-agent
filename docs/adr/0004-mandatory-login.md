# ADR 0004：强制注册登录（移除本地免登录模式）

- 状态：已接受
- 日期：2026-10-13（需求方要求：必须注册登录才能使用）

## 背景

v1.0 设计里客户端有「本地模式」：不登录也能使用本地模型与本地工具，只有市场、同步、上报需要登录（design 4.1 第 6 条）。这带来两个问题：

1. 企业无法保证「谁在用」：无身份即无归属、无审计主体、无配额与策略下发的基础；
2. 用量、激活、市场、同步等功能都建立在账号之上，免登录模式让这些能力天然割裂（用户需要先本地用一段时间再登录，数据归属需要补合并逻辑）。

需求方明确要求：**必须注册登录才能使用**。

## 决策

1. 客户端启动即进入**登录门禁**：未登录（或服务端拒绝会话）时只渲染登录/注册页，不渲染主界面；
2. 登录支持本地账号密码注册与登录；企业 SSO（OIDC，D10）后续接入到同一门禁；
3. 已登录会话靠 refresh token 静默恢复（用户不需要每次输密码），但**需要服务端可达**；
4. 服务端不可达时门禁只提供「重试」，不提供离线绕过；令牌被服务端撤销/账号被禁用时，主进程广播 `cloud:session-lost` 事件，界面立即退回门禁；
5. 原 4.1 第 6 条「本地模式」作废；上报链路的「未登录不入队」保留为防御性约束。

## 后果

- 正面：身份、归属、审计、配额、策略（D11）全部有主体；客户端不需要维护「本地数据登录后补归属」的合并路径；实现更简单（状态机少一个分支）。
- 负面：**服务端不可用时客户端不可用**（含纯本地模型场景）；离线办公场景需要企业自备高可用部署；这一点在发布说明与部署文档中必须写明。
- 与 D14（离线资源状态管控）无冲突：那条讲的是登录之后离线时对已安装资源如何处置。
